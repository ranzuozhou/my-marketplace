## §1 领域定向报告主提示词

build skill Phase 7 调用 `notebook_query()` 时使用。生成结果同时保存为 Note 与 Source（编号 `00c-定向-{topic}领域定向报告`）。

```text
我刚完成本 notebook 的来源导入，请基于全部 source 帮我生成一份「领域定向报告」，目标是把材料重构成从陌生到理解的学习序列。

我的背景：
- 我对这个主题几乎没有系统背景。
- 请不要假设我已经懂专业术语。
- 请先用日常语言解释，再引入专业表达。

请按以下结构输出，每节都引用具体 source：

## 1. 领域归属
- 这个主题属于什么领域？
- 这个领域通常解决哪 5 类问题？
- 它不能解决什么？容易和什么相邻领域混淆？

## 2. 原始困惑翻译
- 列出 5 个新手会有的日常语言问题
- 把每个问题翻译成本领域的专业问题
- 标出每个问题需要的前置概念

## 3. 核心概念地图
- 提取 10-15 个核心概念
- 说明它们的关系（前置 → 高级）
- 标出最容易误解的 3 个概念

## 4. 术语翻译表（取 20 个）
| 术语 | 日常语言 | 专业定义 | 最小例子 | 反例 | 常见误解 |
| ... |

## 5. 成功案例（5 个）与失败案例（5 个）
对每个案例分析"为什么成功/失败"的机制，不只复述故事。
如来源中案例不足，请明确说"来源不足，仅提取到 N 个"。

## 6. 学习路线
从零基础到能理解本 notebook 的推荐路径，标出每段需读哪些 source。

## 7. 推荐 NLM 制品组合
基于来源量和领域特性，推荐生成顺序与 prompt 提示。

【约束】
- 所有关键判断引用具体 source 名称
- 来源中没有的内容标注「推断」或「背景知识」
- 不要编造案例、数据、人名
- 如某节信息不足，请明确说"来源不足"而不是凑内容
```

**调用方式**：

```python
notebook_query(
    notebook_id=nb_id,
    query=DOMAIN_ORIENTATION_PROMPT,
    # 可附加 chat_configure(goal="learning_guide") 让 NLM 切到学习模式
)
```

## §2 三版生成提示词

studio skill `view` 子参数对应的三组 Intent Layer 模板。每个 artifact_type 都有零基础/结构/挑战三个版本。

### 2.1 零基础版（`view=foundation`）

**目标**：让用户第一次听懂。

```text
请生成{topic}的零基础版{artifact_type}。

要求：
1. 完全假设受众没有背景，不要默认懂任何术语
2. 每个抽象概念都配一个生活化类比 + 最小例子
3. 术语少用，必要时先用日常语言解释，再引入专业表达
4. 长度控制在 simple 版（{length_short}），降低进入门槛
5. 结尾给"我现在能回答的 3 个最简单问题"

【约束同 risk-control-templates §2 默认约束】
```

### 2.2 结构版（`view=structural`）

**目标**：建立概念地图与适用边界。

```text
请生成{topic}的结构版{artifact_type}。

要求：
1. 强调概念之间的层级关系（前置 → 核心 → 高级）
2. 每个核心概念配：定义、用途、最小例子、反例、适用边界
3. 提供概念地图（哪些概念互为前置，哪些容易混淆）
4. 长度可以中等（{length_default}），重点在结构清晰
5. 结尾给"判断清单"：遇到新问题时如何判断本知识是否适用

【约束同 risk-control-templates §2 默认约束】
```

### 2.3 挑战版（`view=challenge`）

**目标**：检查是否真的理解。

```text
请生成{topic}的挑战版{artifact_type}。

要求：
1. 重点放在反例、失败案例、常见误用、迁移应用题
2. 至少包含 3 个"看似适用但不适用"的边界情形
3. 至少 2 个迁移应用题（把本主题的原则用到相邻领域）
4. 长度可以适度（{length_default}），密度高
5. 结尾给 5 个"如果错答说明哪个概念没掌握"的诊断题

【约束同 risk-control-templates §2 默认约束】
```

### 2.4 三版联合提示词（一次性生成对比）

```text
请把本 notebook 内容改写成三个学习版本，并指出三版差异：

1. 零基础版：少术语、多类比、多生活化例子
2. 结构版：概念关系、层级、前置知识、适用边界
3. 挑战版：反例、失败案例、迁移题、诊断题

最后给出"三版差异对照表"和"建议学习顺序"。

【约束同 risk-control-templates §2 默认约束】
```

## §3 错题 Root Cause 提示词

query skill Mode D 使用。输入 Quiz 错题列表，输出每题的归因与重学建议。

```text
我刚做完本 notebook 的 Quiz，以下是错题列表：

{错题列表，每题包含：题干、用户答案、正确答案、可选的解析}

请对每道错题做 root cause 分析，输出格式：

## 错题 [编号]
**题干**：{题干}
**用户答**：{用户答}
**正解**：{正解}

**Root Cause 分类**（多选）：
- [ ] 概念误解：核心定义没掌握
- [ ] 例子混淆：把例子和反例混淆
- [ ] 边界不清：对适用范围理解模糊
- [ ] 考试思维：知识懂但题目陷阱没识别
- [ ] 来源记忆错位：把另一个 source 的结论用到了错误场景
- [ ] 推断错误：来源没说，但用户自己推得错

**关键失分点**：{一句话总结到底卡在哪}

**重学建议**：
- 推荐重读 source：{source 名称 + 章节}
- 推荐生成新制品：{audio/slide/quiz 的具体 prompt 提示}
- 推荐再练题：{相邻概念的 1-2 道延伸题}

## 综合分析（错题数 ≥ 3 时）
- 最频繁的 root cause 类型是：{类型}
- 暴露的薄弱概念：{核心概念列表}
- 建议下一轮学习重点：{1-2 个聚焦点}

【约束】
- root cause 必须有依据，不要凭直觉分类
- 重学建议必须引用具体 source 名称
- 综合分析只在 ≥3 题时给出
```

## §4 成功失败案例机制分析

studio (report Create Your Own) 或 build (Phase 7 内嵌) 使用。

```text
请基于本 notebook 中的社区案例、实践案例或经验叙述，做一份「成功与失败机制分析」。

不要只复述案例，要分析机制。

输出格式：

## 1. 成功案例列表
对每个案例：
- 案例背景（一句话）
- 做了什么（关键动作）
- 为什么有效（机制）
- 依赖什么条件（不可缺的前提）
- 可迁移原则（脱离场景后还能用的部分）

## 2. 失败案例列表
对每个案例：
- 案例背景
- 做了什么
- 为什么失败
- 失败类型：概念误解 / 执行问题 / 环境问题 / 目标问题
- 如何避免

## 3. 共同模式
- 成功者共同做对了什么？
- 失败者共同忽略了什么？
- 哪些结论只是个案，不能泛化？

## 4. 给零基础学习者的行动建议
- 先做什么
- 不要做什么
- 如何判断自己是否真的理解（自检指标）

【约束】
- 来源不足时明确说"来源中只有 N 个案例"
- 不要编造案例
- 机制分析必须可追溯到具体 source 段落
```

## §5 来源核查交互提示词

query skill Mode E 使用。详见 `→ ./risk-control-templates.md#4. Source Check 提示词模板`。

补充：当用户主动用此模式时，预先抽取上一轮 conversation 的关键结论：

```text
我刚和你讨论了 {topic}，请帮我对你上一轮回答中的关键结论做来源核查。

【步骤】
1. 先列出你上一轮回答中的关键结论清单（用项目符号，10 条以内）
2. 然后对每条结论按 risk-control-templates §4 的等级体系标注

【约束】
- 抽取结论时不要曲解原意
- 标注严格，宁可标 UNCERTAIN 也不拔高
- 输出最后给"通过率"：DIRECT 条数 / 总条数
```

## §6 术语翻译提示词

studio (report Create Your Own with `report_format="Glossary"`) 使用。

```text
请基于本 notebook 提取一份「术语翻译表」，作为零基础学习者的入门词典。

要求：
- 提取 20 个最核心术语（按出现频率与重要性）
- 每个术语包含 6 列：术语 / 日常语言解释 / 专业定义 / 最小例子 / 反例 / 常见误解
- 用表格输出，便于复习
- 标记 5 个"最容易误解"的术语（加 ⚠️）
- 标记 3 个"前置必懂"的术语（加 ⭐）

【约束同 risk-control-templates §2 默认约束】
```

## §7 理解度自检对话

query skill Mode F 使用，结合 `understanding-metrics.md` 的 7 项指标。

```text
请用对话方式帮我做一次「理解度自检」。

【步骤】
1. 你扮演耐心的提问者，依次问我下列 7 项问题：
   1) 你能在 10 分钟内说出本主题的大图吗？请试着说一段。
   2) 你能列出至少 5 个核心术语并解释吗？
   3) 你能说出 3 个反例 / 不适用场景吗？
   4) 你能解释成功 / 失败案例的机制吗（不要复述故事）？
   5) 上次 Quiz 错题命中率怎样？最薄弱的概念是？
   6) 关键结论你能在原文找到依据吗？
   7) 24 小时后你预期还能复述吗？哪些可能忘？

2. 我每答完一题，你做两件事：
   a. 对照本 notebook 来源，给我一个「一致性评分」（1-5）+ 简要反馈
   b. 如果薄弱（评分 ≤ 3），告诉我应该回看哪个 source 的哪一节

3. 7 题答完后，给出综合「理解度仪表盘」：
   - 7 项评分
   - 总体级别：入门 / 熟悉 / 掌握
   - 下一步建议（重读 / 重生成制品 / 再做 quiz / 进入下一主题）

【约束同 risk-control-templates §2 默认约束】
```

输出最终保存为 notebook 的 `99-自检-理解度仪表盘-{YYYYMMDD}` Note。

## 模板使用约定

1. **不要内联粘贴**：所有 skill 在使用时通过 `→ ./learning-loop-templates.md#§N` 引用，不要把完整 prompt 复制到 SKILL.md body 里。
2. **占位符替换**：`{topic}`、`{audience}`、`{length_short/default}` 等由调用方在 runtime 替换。
3. **约束句拼接**：所有模板末尾都引用 `risk-control-templates.md §2`，由 studio/query 在 runtime 自动追加。
4. **多语言**：模板默认中文。如 NLM `language="en"`，调用方需翻译模板（v2.0 仅支持中文，v2.1 计划增 en）。
