# Understanding Metrics — 7 项理解度量化指标

> 方法论文档 §9 的工程化落地。承载：7 项指标定义、自评量表、NLM 验证逻辑、仪表盘 Note 模板。

## 7 项指标速览

| # | 指标 | 评估方式 | 数据来源 | 自动化级别 |
|---|---|---|---|---|
| 1 | 10 分钟说大图 | 用户自评 + NLM 一致性评分 | 用户口述 → query Mode F | 半自动 |
| 2 | 列出核心术语 | 用户复述 ≥5 项 + NLM 验证 | 用户复述 → query Mode F | 半自动 |
| 3 | 说出反例 | 用户给 ≥3 个反例 + NLM 验证 | 用户口述 → query Mode F | 半自动 |
| 4 | 案例机制分析 | 用户分析 ≥1 成功 + ≥1 失败案例 | 用户口述 → query Mode F | 半自动 |
| 5 | Quiz 命中率 | 答对题数 / 总题数 | quiz 结果 | 全自动 |
| 6 | 来源核查通过率 | DIRECT 结论数 / 总结论数 | query Mode E 结果 | 全自动 |
| 7 | 24h 复述能力 | 24 小时后回访 + NLM 一致性评分 | 用户回访 → query Mode F | 人工触发 |

---

## 1. 10 分钟说大图

**定义**：用户能否在 10 分钟内独立说出本主题的核心问题、关键概念、适用边界，不看材料。

**评估流程**：
1. query Mode F 提示用户：「请用 10 分钟时间，向一个零基础朋友讲清楚本主题。」
2. 用户口述（粘贴或语音转文字）
3. NLM 对照 source，按 5 级评分：
   - 5 = 准确、完整、能区分核心与次要
   - 4 = 准确、覆盖大部分要点
   - 3 = 大致正确，遗漏关键点
   - 2 = 有事实错误或概念混淆
   - 1 = 难以辨认或基本不对
4. NLM 给反馈：「你说对了什么 / 漏了什么 / 错了什么」

**通过线**：评分 ≥4。

---

## 2. 列出核心术语

**定义**：用户能否独立列出 ≥5 个核心术语并用 1-2 句话解释。

**评估流程**：
1. 提示用户：「请列出至少 5 个本主题的核心术语，每个用 1-2 句话解释。」
2. NLM 对每条术语：
   - 与 source 中的定义对照
   - 标注准确度（accurate / partial / wrong / not_in_source）
   - 给修正建议
3. 统计 accurate 占比

**通过线**：accurate 占比 ≥70%（即 5 个中 ≥4 个对）。

---

## 3. 说出反例 / 不适用场景

**定义**：用户能否说出至少 3 个本主题不适用的场景或反例。

**评估流程**：
1. 提示用户：「列出至少 3 个本知识不适用 / 容易误用 / 反例的场景。」
2. NLM 对每条反例：
   - 验证是否真的是反例（而不是边缘适用情形）
   - 检查是否能在 source 中找到依据（或属合理推断）
3. 标注 valid / invalid / debatable

**通过线**：valid ≥3 个。

> 这一项是方法论里特别强调的——能说反例往往比能说定义更能证明理解。

---

## 4. 案例机制分析

**定义**：用户能否分析至少 1 个成功案例 + 1 个失败案例的机制（不只复述故事）。

**评估流程**：
1. 提示用户：「选 1 个成功案例和 1 个失败案例，分别说：做了什么 / 为什么有效（或失败）/ 依赖什么条件 / 哪些是可迁移的原则。」
2. NLM 评估「机制深度」：
   - mechanistic：分析了因果链
   - descriptive：只复述案例
   - mixed：部分机制、部分复述
3. 综合两个案例给一个机制深度分

**通过线**：两个案例至少有一个达到 mechanistic。

---

## 5. Quiz 命中率

**定义**：最近一次 Quiz 的正确率。

**评估流程**：
1. 自动从 quiz 制品的结果读取（用户在 query Mode D 输入错题列表时附带）
2. 命中率 = 答对数 / 总题数

**通过线**：≥70%（中等难度），≥80%（简单），≥60%（困难）。

**附加**：错题分布按 root cause 类型统计（query Mode D 的输出），找出最频繁的薄弱类型。

---

## 6. 来源核查通过率

**定义**：用户对自己最近一段总结/解释的关键结论，能在 source 中找到依据的比例。

**评估流程**：
1. 用户提供一段总结或解释（粘贴）
2. query Mode E 对每个结论标注 DIRECT / INFERRED / BACKGROUND / UNCERTAIN / CONTRADICTED
3. 通过率 = DIRECT 数 / 总结论数

**通过线**：≥70%。

> 详见 `→ ./risk-control-templates.md#4. Source Check 提示词模板`

---

## 7. 24h 复述能力

**定义**：24 小时后用户能否独立复述大图与核心要点。

**评估流程**：
1. 学习闭环结束时，learn skill 在 `99-自检-理解度仪表盘` Note 中记录预约时间
2. 24h 后用户主动触发 `/mj-nlm:query --mode=recall <notebook_id>`
3. 流程同指标 1，但要求"不查材料"
4. 对比首次评分，看保留率

**通过线**：评分 ≥3（即 24h 后仍能说出大致框架）。

**附加**：保留率 = 24h 后评分 / 首次评分。

## 仪表盘 Note 模板

query skill Mode F 完成后，把结果保存为 notebook 的 Note：

```markdown
# 理解度仪表盘 — {topic} ({YYYYMMDD HH:MM})

## 7 项评分

| # | 指标 | 得分 | 通过线 | 状态 |
|---|---|---|---|---|
| 1 | 10 分钟说大图 | 4/5 | ≥4 | ✅ |
| 2 | 核心术语 | 5/5 (5/5 准确) | ≥4/5 | ✅ |
| 3 | 反例 | 3 (3 valid) | ≥3 | ✅ |
| 4 | 案例机制 | mechanistic | mechanistic | ✅ |
| 5 | Quiz 命中率 | 8/10 (80%) | ≥70% | ✅ |
| 6 | 来源核查通过率 | 75% | ≥70% | ✅ |
| 7 | 24h 复述 | 待回访 ({YYYY-MM-DD HH:MM}) | — | ⏳ |

## 总体级别
- 当前：**熟悉**（6/6 已评估指标通过；7 待回访）
- 提升路径：完成 24h 复述以达到「掌握」级

## 薄弱点（需要重学）
- {从 indicator 1-6 评分中提取低分项}

## 推荐动作
1. {基于薄弱点的 source / artifact 重生成建议}
2. {下一主题进入建议}

## 24h 复述安排
- 提醒时间：{YYYY-MM-DD HH:MM}
- 提醒方式：手动触发 `/mj-nlm:query --mode=recall {notebook_id}`
- 预期评分：≥3
```

**Note 命名**：`99-自检-理解度仪表盘-{YYYYMMDD}-{HHMM}`

## 三级总体评级

基于 7 项指标的整体得分：

| 级别 | 通过指标数 | 描述 |
|---|---|---|
| **入门** | 1-3 项通过 | 知道大概在讲什么，能用日常语言说一两句 |
| **熟悉** | 4-6 项通过 | 能用术语讨论，能识别反例，能解释案例机制 |
| **掌握** | 7 项全通过 | 24h 后仍能复述，关键结论可追溯，能迁移到相邻问题 |

注：单次仪表盘最多达到「熟悉」（指标 7 需要 24h 回访），「掌握」需要回访通过后才能确认。

## 与 learn orchestrator 的衔接

learn skill Phase 8 调度本指标体系，触发顺序：

1. 先读 `quiz_result`（指标 5）和最近的 Source Check 结果（指标 6）—— 全自动
2. 再启动 query Mode F 半自动对话（指标 1-4）
3. 最后写 Note + 安排 24h 提醒（指标 7）

如果指标 1-4 评分整体偏低（平均 < 3），learn 在 Phase 8 结束后跳回 P3-P5（重生成 mind_map / video / slide）—— 这是闭环回路。
